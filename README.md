## Summary

Kaizen is continuous improvement in small steps against a written standard. This paper is a descriptive case study of kaizen in an agent software factory, a system in which AI coding agents write, test and ship software under rules people set. The factory studied is an agent team run with Agent Scrum. We define a method-independent improvement loop and map Agent Scrum and nine other published accounts onto it. In 16 days to 5 November 2026 the team filed 417 retrospective issues; of 20 sampled done issues, 18 named a merged change and none recorded a measured effect. On 6 November the team added an evaluation step: each retrospective issue states a prediction, and a later wrap records a verdict. In the next 17 days, 303 of 323 retrospective issues (94%) carried a prediction and 129 of 156 due predictions (83%) received a verdict: 95 held, 18 did not, 16 could not be measured. All 129 verdicts ended in keep; none in reverse. The agents that write a prediction also grade it, and we did not audit whether the measurements ran, so the figures show records, not effects. The prediction on authorship failures could not be tested.

## What this is, and is not

This is a descriptive case study of one agent team run with Agent Scrum, in one deployment over 17 days. It reports what the team's records show. It is not a controlled study and does not show that the evaluation step improved outcomes. Earlier drafts were private and titled "Kaizen for Agents"; version 0.7 was the first public version; version 0.8 adds section 9.4.
